## 1. 播放状态专项（改动面最大，建议单独立项）

**现状**
- `app/src/main/kotlin/com/yichao/evilgodxu/data/music/playback/MusicPlaybackState.kt`
  —— 音乐播放器状态持有者（悬浮窗级共享单例状态），含 **66 处** Compose 可变状态声明
  （`mutableStateOf` / `mutableIntStateOf` / `mutableLongStateOf` / `mutableFloatStateOf`），
  并直接持有 `MediaController`/`Player`、`playlist`、`currentTrack`、`playMode`、`errorMsg`、
  搜索状态（`searchQuery`/`searchResults`/`searchPending`…）、定时关闭（`timerMinutes`/`timerRemaining`/`timerAutoStopped`）等。
- 由 `data/music/panel/MusicPanelStateHolder.kt` 持有并暴露（`AppContainer.stateHolder`）。
- UI 经 `LocalMusicPanelStateHolder.current.state` 读取，并**直接写属性**（如 `state.currentTrack = ...`、`playbackState.setSearchQuery(...)`、`playbackState.searchResults = emptyList()`）。

**规范依据**（`开发规范.md` 状态管理）
- 页面状态统一 `StateFlow<UiState>`。
- `UiState` 必须不可变，列表项提供稳定唯一键。
- 一次性事件用 Channel 或 SharedFlow，不要塞进 `UiState`。

**影响面**：`screens/home/**`、`ui/component/**`（MusicPanel*/MiniPlayer*）、`floatingwindow/**`、`service/MusicPlaybackService.kt`。

**建议改法（分阶段，每阶段可编译可手测）**
1. 抽出只读不可变 `UiState`（data class）；把外部写入点改为意图方法（`fun`）暴露。
2. 内部用 `MutableStateFlow<UiState>` 收敛，逐步移除 `mutableStateOf`；列表项用稳定 ID。
3. 一次性事件（如 `errorMsg`、`timerAutoStopped`、错误横幅）改 `Channel`/`SharedFlow`，不放进 UiState。

**风险**：回归面大（播放、悬浮窗、通知、歌词/封面）。禁止一次性大爆改，务必小步 + 每步 `assembleDebug` + 手测播放。

**相关文件**
- `data/music/playback/MusicPlaybackState.kt`、`data/music/playback/MusicPlayerHelper.kt`、`data/music/panel/MusicPanelStateHolder.kt`
- `data/playlist/PlaylistStore.kt`（见第 4 项，`playlists` 同为 `mutableStateOf`，建议合并处理）
- `service/MusicPlaybackService.kt`、`floatingwindow/MiniPlayerViewManager.kt`、`floatingwindow/MusicPanelViewManager.kt`

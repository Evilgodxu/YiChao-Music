> 版本: v1.0.0 | 整理日期: 2026-08-27

代理音源（Proxy Source）是一个 JSON 文件，描述一个第三方音乐接口的调用方式：

- **搜索**（`search`）：如何按关键词搜索歌曲
- **播放地址**（`url`）：如何按曲目与音质档位换取可播放/可下载的直链
- **歌词**（`lyric`）：如何获取 LRC 歌词
- **封面**（`pic`）：如何按搜索返回的封面 ID 换取封面图片地址

导入后，应用在**对应平台**的在线歌曲搜索、音质选择、播放与缓存（缓存即按解析出的直链下载到本地）都会优先走该音源；音源不可用时自动回退应用内置解析。

## 二、快速开始

1. 按本文档编写一个 JSON 文件。
2. 在应用「设置 → 代理音源 → 导入音源」中选择「本地导入 / 链接导入 / 文本导入」。

## 三、顶层结构

```jsonc
{
  "name": "音源名称",            // 必填，字符串；同名重复导入时覆盖旧音源,应用中会显示
  "version": "1.0.0",           // 可选，版本号,应用中会显示
  "author": "作者",              // 可选,应用中不显示
  "homepage": "https://...",    // 可选，官网/聚合站点,应用中不显示
  "description": "描述",        // 可选，应用中不显示
  "platforms": {                 // 必填，至少覆盖一个受支持平台
    "wy":    { /* 平台定义 */ },
    "qq":    { /* 平台定义 */ }
  }
}
```

### 受支持平台

平台键必须使用以下短标识之一，其余键被忽略：

| 平台键 | 对应应用内平台 |
| ------ | -------------- |
| `wy`   | 网易云         |
| `qq`   | QQ 音乐        |
| `kg`   | 酷狗           |
| `kw`   | 酷我           |
| `mg`   | 咪咕           |

---

## 四、平台定义

每个平台下可声明五类动作，均为可选：**只声明需要的动作**，未声明的动作自动回退内置解析。

```jsonc
{
  "wy": {
    "search":   { /* 动作定义 */ },
    "url":      { /* 动作定义 */ },
    "lyric":    { /* 动作定义 */ },
    "pic":      { /* 动作定义 */ },
    "playlist": { /* 动作定义 */ }
  }
}
```

`playlist` 动作与其余动作不同：它不针对单曲，而是**按歌单 ID 拉取整个歌单的歌曲列表**，供自定义歌单的「从链接导入歌单」功能使用。

## 五、动作定义（Action）

```jsonc
{
  "method": "GET",                    // 可选，GET / POST，默认 GET
  "url": "https://api.example.com",   // 必填，请求地址模板
  "params": {                          // 可选，参数模板（见下表）
    "types": "search",
    "name": "{keyword}"
  },
  "query": { },                        // 可选，POST 时追加到 URL 的查询参数
  "headers": {                         // 可选，请求头
    "User-Agent": "lx-music"
  },
  "qualities": {                       // 仅 url 动作有意义：音质档位映射
    "standard": 128,
    "high": 320,
    "lossless": 999
  },
  "result": { /* 结果映射，见第六节 */ }
}
```

### 请求语义

- **GET**：`url` 与 `params` 拼出查询串，如 `https://api.example.com?types=search&name=晴天`。
- **POST**：`params` 以 `application/x-www-form-urlencoded` 作为请求体；`query` 追加到 URL 查询串。
- `headers` 按模板渲染后原样发送。

### 占位符（Placeholder）

`url`、`params`、`query`、`headers` 中可使用 `{name}` 占位符，运行时替换：

| 占位符        | 适用动作       | 含义                                                         |
| ------------- | -------------- | ------------------------------------------------------------ |
| `{keyword}`   | search         | 搜索关键词                                                   |
| `{page}`      | search / playlist | 页码（搜索固定 1；歌单从 1 起逐页递增）                     |
| `{count}`     | search / playlist | 每页条数（搜索固定 50；歌单默认 50）                        |
| `{playlistId}`| playlist       | 歌单 ID（由分享链接解析出）                                 |
| `{id}`        | url / lyric    | 曲目数字 ID（搜索结果的 `id` 字段）                           |
| `{sourceId}`  | url / lyric    | 平台自定义标识（搜索结果的 `sourceId` 字段，缺省同 `{id}`）   |
| `{coverId}`   | pic            | 封面 ID（搜索结果的 `coverId` 字段）                          |
| `{quality}`   | url            | 当前音质档位的映射值（来自 `qualities`）                      |
| `{title}`     | 全部动作       | 歌曲标题                                                     |
| `{artist}`    | 全部动作       | 歌手名                                                       |
| `{album}`     | 全部动作       | 专辑名（当前为占位保留）                                      |
| `{duration}`  | 全部动作       | 时长毫秒数（当前为占位保留）                                  |

若某占位符缺少取值，按空字符串渲染（可借此做“缺省省略”）。`qualities` 可整体省略：此时 `url` 动作对三档音质均生效，`{quality}` 渲染为空字符串，适合「接口固定返回同一音频直链」的音源。若 `qualities` 只声明了部分档位，未声明的档位**不生效**，自动回退内置解析。

### 音质档位映射（`qualities`）

`url` 动作用 `qualities` 把应用的三档音质映射为聚合接口的音质代号：

| 档位键       | 应用内含义         | GD Studio 示例 |
| ------------ | ------------------ | --------------------- |
| `standard`   | 标准（128kbps）     | `128`                 |
| `high`       | 高品（320kbps）     | `320`                 |
| `lossless`   | 无损（FLAC/Hi-Res） | `999`                 |

## 六、结果映射（`result`）

结果字段均为 **JSONPath**（子集见第七节），指向响应体中的取值。字段按动作类型区分：

### search 动作

| 字段         | 说明                                                           |
| ------------ | -------------------------------------------------------------- |
| `list`       | 结果数组路径；缺省时响应体本身为数组                           |
| `id`         | 曲目数字 ID（必填能力项，缺省回退 `sourceId` 的稳定哈希）      |
| `title`      | 歌曲名                                                         |
| `artist`     | 歌手名；值为字符串数组时自动以 ` / ` 拼接                       |
| `sourceId`   | 平台自定义标识（如 QQ 的 songmid、酷狗 hash），url/lyric 使用   |
| `coverUrl`   | 封面直链（与 `coverId` 二选一）                                |
| `coverId`    | 封面 ID，经 `pic` 动作换取真实地址；两者都缺省则无封面          |
| `duration`   | 时长毫秒数（可选）                                             |

搜索结果的 `id` 还会作为列表去重键：同一音源内重复 ID 只保留一条。

### playlist 动作

`playlist` 动作的结果映射复用 search 的 `list`/`id`/`title`/`artist`/`coverUrl`/`coverId`/`sourceId`/`duration` 字段，另支持：

| 字段           | 说明                                                         |
| -------------- | ------------------------------------------------------------ |
| `playlistName` | 歌单名称 JSONPath；解析失败时应用回退默认名「导入歌单」        |
| `total`        | 歌单歌曲总数 JSONPath；用于判断分页是否拉满                   |

**分页语义**：应用从第 1 页开始逐页请求（`{page}` 递增），直到满足以下任一条件停止：

1. 某页歌曲数组为空；
2. `total` 配置且累计去重数量 ≥ total；
3. 某页返回数量不足一页（< `{count}` 对应的值）；
4. 本页无新增条目（接口重复返回同一页）。

歌单接口通常需要 token 认证，按接口要求在 `params`/`headers` 中声明即可。

### url / pic 动作

| 字段   | 说明                                 |
| ------ | ------------------------------------ |
| `url`  | 返回的直链；为空字符串视为解析失败    |

**响应体即直链**：`url`（及 `pic`）动作的响应体可以直接就是音频/图片直链——纯文本 URL，无需 JSON 包装。此时 `result` 可整体省略，应用把响应体原样当作直链解析（`result.url` 配置为 `"$"` 效果相同）；若响应体是 JSON（如 `{"url": "https://..."}`），则仍需用 `result.url` 指明字段路径。直链为 `http://` 或 `https://` 均可直接播放。

`url` 动作解析出的直链会同时用于**播放**与**缓存下载**（应用按直链后缀推断文件格式后存入系统下载目录）。

### lyric 动作

| 字段    | 说明             |
| ------- | ---------------- |
| `lyric` | LRC 原歌词文本   |
| `tlyric`| 翻译歌词文本（可选，按时间戳合并） |

## 七、JSONPath 子集

仅支持以下语法，按 `.` 分段、`[n]` 下标：

| 表达式                  | 含义                          |
| ----------------------- | ----------------------------- |
| `$`                     | 根节点（响应 JSON 本体）      |
| `$.data.list`           | 依次取对象字段                |
| `$.songs[0].name`       | 取数组第 0 项后再取字段       |
| `$(省略 $. 前缀也可)`    | 解析时自动剥去 `$`            |

提取失败或类型不符时返回空，交由内置解析回退。

---

## 八、运行时语义

1. **生效范围**：仅作用于 JSON 中声明了动作的平台与动作类型。
2. **优先级**：代理优先 → 失败（网络异常 / 返回空 / 字段解析失败）→ 自动回退内置解析。
3. **多音源冲突**：同一平台被多个音源覆盖时，**各动作独立取最近导入且配置了该动作的音源**——不同音源可分别覆盖搜索/播放/歌词/封面/歌单等动作而不互相顶替（例如歌单同步音源只提供 `playlist`，不影响其它音源的 `url` 生效）。
4. **即时性**：导入、移除后立即影响后续搜索与播放，无需重启。
5. **频率控制**：请按聚合接口的限额设计调用频率；应用不会额外限速。搜索结果封面为逐条换取（默认最多 8 张，每张一次请求）。
6. **缓存来源**：缓存下载使用的就是音源解析出的直链，与播放同源。

## 九、示例解析

以网易云 `url` 动作为例：

```jsonc
{
  "method": "GET",
  "url": "https://music-api.gdstudio.xyz/api.php",
  "params": { "types": "url", "source": "netease", "id": "{id}", "br": "{quality}" },
  "qualities": { "standard": 128, "high": 320, "lossless": 999 },
  "result": { "url": "$.url" }
}
```

用户选择「高品」播放某曲目（`id=2652820720`）时，应用发出：

```
GET https://music-api.gdstudio.xyz/api.php?types=url&source=netease&id=2652820720&br=320
```

响应 `{ "url": "https://m801.music.126.net/.../xxx.mp3", "br": 320, ... }`，取 `$.url` 作为播放与缓存直链。

若接口直接返回音频直链（纯文本，非 JSON），则连 `result` 都可省略：

```jsonc
{
  "name": "直链音源示例",
  "platforms": {
    "wy": {
      "url": {
        "url": "https://api.example.com/get?id={id}",
        "headers": { "User-Agent": "lx-music" }
      }
    }
  }
}
```

接口直接返回 `https://cdn.example.com/audio.mp3?sign=xxx`，应用把它作为播放与缓存直链直接使用。该音源只声明了 `url` 动作：搜索/歌词/封面自动回退内置解析，`qualities` 省略时任意音质均执行该动作。

## 十、开发者注意事项

- `qualities` 中 `standard`/`high`/`lossless` 三键可只声明部分：未声明的档位回退内置。
- 聚合接口返回的直链通常**带时效签名**，请勿做长时间缓存，应用侧按需实时解析。
- 若接口要求认证（如 `X-Token`），在 `headers` 中声明即可；但请确保返回 `trusted` 结果，否则部分平台会拒绝服务。
- 在 `headers` 中按接口要求设置 `User-Agent`（如 `LX-Music-Mobile`），避免风控。
